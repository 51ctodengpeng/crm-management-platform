### B. 结构重构（2 项，纯搬迁 + 兼容层）

**B1. `utils.py` 拆分出 `dictionary.py`（635 行 → 467 行 + 218 行）**

`utils.py` 原来是"文件 + 表单 + 字典 + 日志 + 权限 + 统计"六件事挤在一起，改字典逻辑得先绕过文件工具函数。现把**选项字典与语义映射**整体搬到 `dictionary.py`：

- `option_items / option_default / option_usage / option_extra / option_is_protected`
- `order_with_other_last / merge_local_choice`
- `status_kind / status_color / status_names_by_kind / level_color / STATUS_KIND_COLORS`
- `transfer_methods / is_transfer_method / clear_option_cache`

`utils.py` 顶部保留同名转出口（`from dictionary import ...`），因此 **30 多处 `from utils import option_items` 一行都不用改**；测试用 `getattr(utils, n) is getattr(dictionary, n)` 验证转出口指向同一对象。

**B2. `routes/backup.py` 拆分出 `backup_store.py`（386 行 → 146 行 + 361 行）**

原来路由文件里混着 sqlite3 online backup、`subprocess` 调 `mysqldump`/`mysql`、zip 打包、目录拷贝四种机制。现按职责切开：

- `backup_store.py`：路径、快照、打包、列举、规模校验、恢复锁、恢复流程（数据层）
- `routes/backup.py`：取参数、权限、flash、跳转（HTTP 层），并把 `_resolve_backup()` 提出来给 download/delete/restore 三处共用

`create_backup` 仍在 `routes.backup` 里可导入（`__all__` 显式保留），历史调用方不受影响。

### C. 并发一致性加固（1 项）

**C1. 对账 check-then-act 加锁**（`routes/finance.py`）

`_check_reconcile` 读"已收合计"判断超收、`_do_reconcile` 再写"已对账"，两步之间原本无锁。新增 `_reconcile_guard(project_id)`：

- 进程内：按项目 id 的 `threading.Lock`（覆盖生产 `2 worker × 4 threads` 里的线程竞争）
- 跨进程：MySQL 下 `SELECT id FROM project ... FOR UPDATE` 行锁
- 死锁/锁等待超时 → 转成 `ReconcileBusy`，单笔对账回滚并提示"正在被另一笔对账占用，请稍后重试"；批量对账**整批回滚**并明确告知未完成（保持原有"要么全成、要么全不成"语义）

串行使用时只多一次极廉价的加锁，金额计算与提示文案不变。
