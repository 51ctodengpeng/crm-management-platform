# 客户管理系统（Flask + SQLite）

轻量内部 CRM：客户信息、项目记录，支持上传合同 / 发票 / Word / PPT 等附件。
文件存本地磁盘，数据库只存元信息；**界面为腾讯云风格淡蓝科技主题**。

## 快速开始（打包成 EXE，推荐给非技术用户）

```bat
build_exe.bat
```

双击等待几分钟即可得到 **dist\CRMSystem.exe**（单文件，无需安装 Python）：

- **双击即用**：自动建表、自动创建管理员（首次运行控制台会打印账号密码）、自动打开浏览器
- 数据落在 EXE 同级目录（`crm.db` + `uploads\` + `.secret_key`），**整个文件夹拷走即可迁移**
- EXE 放在只读目录（如 Program Files）时，数据自动改存 `%LOCALAPPDATA%\CRMSystem`
- 常用参数：`CRMSystem.exe --port 9000`、`--host 0.0.0.0`（允许局域网访问）、`--no-browser`、
  `--reset-admin 新密码`（忘记管理员密码时重置）
- **重复双击不会开第二个服务**，而是直接帮你打开浏览器
- 单文件 EXE 首次启动需自解压，等待 3~10 秒属正常；个别杀软可能误报，添加信任即可

打包细节见下文「打包为 EXE」章节。

## 快速开始（源码方式运行）

```bat
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python init_db.py        :: 建表 + 创建管理员 admin / admin123
.venv\Scripts\python desktop.py        :: 启动（与 EXE 行为一致）
```

浏览器访问 **http://127.0.0.1:8081** ，默认账号 `admin` / `admin123`（登录后请立即在「修改密码」中更换）。

也可以直接双击 `run.bat` 一键启动。启动时自动执行自举（建表 / 补列 / 建默认管理员），无需手动初始化。

### 升级已有数据库（重要）

从旧版本升级时执行一次，脚本只补缺失的字段与新表，**不丢数据**：

```bash
python migrate.py
```

## 打包为 EXE

```
erp/
├── build_exe.py           一键打包脚本（build_exe.bat 是它的双击入口）
├── crm.spec               PyInstaller 配置（打入 templates/static，收集 sqlalchemy 方言）
├── tools/make_icon.py     生成应用图标（纯 Python，无需 Pillow）
└── dist/CRMSystem.exe     打包产物
```

- **单文件模式**（默认）：`python build_exe.py` → 一个 EXE，方便分发
- **目录模式**（启动更快、免自解压）：`python build_exe.py --onedir` → `dist\CRMSystem\` 整个文件夹
- 资源目录（模板/静态文件）随包内置；数据目录（数据库/附件/密钥）独立于程序，
  程序更新替换 EXE 不影响已有数据
- 打包引擎：PyInstaller + waitress（生产级 WSGI，非 Flask 调试服务器）

### 客户来源渠道

预设 `互联网 / 客户介绍 / 老客户续约 / 展会活动 / 电话拜访 / 渠道代理 / 招投标 / 行业社群 / 其他`，
下拉选择「自定义…」后可自由填写（例：行业协会推荐）。自定义渠道同样入库、参与筛选，
并出现在仪表盘的「客户来源渠道分布」中。筛选下拉会自动带上库里已用过的自定义渠道。

### 金额、税点与服务/付款方式

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| project_amount | 金额（元，2 位小数） | **不含税**合同金额 |
| tax_rate | 0 ~ 100，默认 **6**（%） | 税点；填 0 表示不含税，两项金额相等 |
| tax_included_amount | 金额（元，2 位小数） | **含税价格** = 不含税 ×（1 + 税点/100），四舍五入到分 |
| service_mode | `远程服务` / `现场服务` / `远程+现场` | 服务方式，决定是否出差驻场 |
| payment_method | `支付软件转账` / `现金支付` | 约定的付款方式 |
| pay_method（收款记录） | 同 payment_method | 实际到账方式 |
| pay_channel | `微信` / `支付宝` / `银行转账` / `云闪付` / `其他` | 仅转账时有值 |
| status（收款记录） | `pending` 待对账 / `matched` 已对账 | 只有已对账才计入已收 |

**双向计算**：表单里改「合同金额」即时正算含税价，改「含税价」即时反算合同金额，
两者用同一公式与同一舍入规则（Python 端 `Decimal ROUND_HALF_UP`，前端 `round2` 对齐），
提交后服务端按隐藏字段 `amount_basis`（`net` / `gross`）重新计算，不采信前端结果，保证一致。

### 转账对账逻辑

1. 项目详情页「收款与对账」登记收款（金额、方式、渠道、流水号、到账日期、付款方、备注），保存后进入 **待对账**；
   转账必须填交易流水号，且流水号在库内唯一（`ux_payment_trade_no` 部分唯一索引，现金记录不参与）。
2. 核对微信/支付宝/银行账单无误后点「对账」，逐条校验：
   金额 > 0；转账需有流水号且未被其他已对账记录占用；`已对账 + 本笔 ≤ 应收含税价`（超出需显式勾选「允许超收」）。
3. 校验通过写入 `status=matched`、`reconciled_at/by`，该笔才计入已收；任一条件不满足则整笔不落库并提示原因。
4. 对账口径：**应收 = 项目含税价**，**已收 = 已对账金额合计**，**差额 = 应收 − 已收**；
   项目资金状态自动判定为 未收款 / 部分收款 / 已结清 / 超收。撤销对账需「删除」权限，撤销后金额退回待对账。

## 账号体系与注册审批

```
新用户注册 → status=pending（待审批）→ 管理员在「账号管理」通过 → status=active 才能登录
                                    └→ 拒绝 → status=rejected（登录时告知拒绝原因）
```

- **注册页**：账号/姓名/手机/部门/邮箱/申请说明，前端与后端双向校验（账号格式、重名、邮箱、密码强度、两次一致）
- **登录拦截**：按状态给明确提示 —— 待审批 / 已拒绝（附原因）/ 已停用 / 账号密码错误
- **管理员审批**：通过、拒绝（可填原因）、停用、启用、设为/取消管理员、重置密码、维护资料、删除
- **待审批提醒**：侧边栏「账号管理」红色角标 + 仪表盘审批横幅，管理员一进来就能看到
- **安全兜底**：不能停用/删除/降级自己；系统必须保留至少一名管理员；普通用户访问账号管理被拦截

## 权限模型：角色 + 数据范围 + 项目级操作

采用 RBAC（功能入口）与 ACL（数据范围）混合模型，划分方式与同类企业系统一致：

| 层级 | 取值 | 说明 |
| --- | --- | --- |
| 角色 Role | 管理员 / 普通成员 | 管理员拥有全部数据与全部操作；普通成员受下面两层约束 |
| 数据范围 Scope | 全部数据 / 仅授权项目 | 默认「仅授权项目」；未授权项目在列表、搜索、统计、导出中均不可见 |
| 操作类型 Action | 查看 / 修改 / 删除 | 项目粒度授权，向下包含：删除 ⊃ 修改 ⊃ 查看 |

- **入口**：系统管理 → 权限管理 → 选择成员 → 逐项目勾选（支持按客户批量授权、全选、筛选）
- **附件继承项目权限**：预览/下载=查看，上传/改备注=修改，删除=删除
- **新增客户/项目**是独立的全局开关（`can_create`），与项目级授权互补
- **删除客户**仅「全部数据」范围可执行（会连带删除其名下全部项目，避免误删未授权数据）
- 数据范围切到「全部数据」后，原有项目授权记录保留，切回「仅授权项目」时自动生效
- 存量账号升级时保持原有可见性（自动置为「全部数据」），新注册/新建账号默认「仅授权项目」

- **长文件名智能缩略**：中文按 2 字符宽度计算，保留头尾与扩展名
  `2026年度AD域控维保服务合同及技术服务附件清单最终确认版.pdf` → `2026年度AD域控维保服务合….pdf`，
  鼠标悬停显示完整文件名；`title` 属性保留原名，操作按钮固定宽度不被挤压
- **拖拽上传**：拖入或点选，支持一次多选、重复文件自动去重、可逐个移除，上传前显示已选清单与按钮计数
- **打包下载**：一键把某项目全部附件打成 zip（内部重名自动加序号，保留原始文件名）
- **附件备注**：随手标注「已盖章原件」「2026 年度维保合同」，可随时编辑
- **按类别归档**：合同 / 发票 / 验收单 / 报告 / 其他（类别走后台字典，可自行增改），列表直接显示分类徽标
- **版本自动归并**：同一项目下「文件名主干」相同的再次上传，自动成为 v2 / v3，列表只显示最新版，
  历史版本折叠在下方可随时打开；旧版本文件不删除，方便追溯合同改版过程
- **在线预览**：PDF / 图片直接预览；docx / xlsx / pptx / txt 提取纯文字在线查看（不下载也能确认内容），
  其余类型提示下载查看
- **统计信息**：附件数量、合计大小、上传人、上传时间一目了然

## 安全设计

1. **登录鉴权**：Flask-Login 全局拦截；`is_active` 与审批状态绑定，未审批账号无法建立会话
2. **密码存储**：werkzeug 哈希，不落明文；管理员重置后需本人自行修改
3. **CSRF 防护**：`CSRFProtect` 全局开启，所有 POST 表单携带 `csrf_token`
4. **文件上传**：黑名单（exe/bat/sh/php/jsp/ps1…）+ 白名单双重后缀校验；物理文件名 UUID；单文件 ≤ 20MB
5. **路径安全**：附件读取经 `resolve_abs_path()` 校验，必须落在 uploads 目录内，杜绝路径穿越
6. **附件不可直链**：Nginx 对 `uploads/` 显式 `deny all`，只能走带鉴权的下载接口
7. **SECRET_KEY 不硬编码**：环境变量 → `.secret_key` 文件 → 自动随机生成
8. **删除一致性**：删客户 / 项目先整份快照进回收站（含项目、收款、回款计划、跟进、附件元信息），
   再删业务数据；附件磁盘文件保留，恢复时按快照重新关联；彻底删除才清理文件
9. **登录防护**：连续 5 次密码错误临时锁定 15 分钟（正确密码同样拒绝），管理员可在账号管理一键解锁
10. **密码强度**：新密码至少 8 位且同时包含字母与数字，拒绝常见弱口令
11. **会话安全**：登录成功后重建会话（防会话固定）；空闲 120 分钟自动退出；Cookie HttpOnly + SameSite=Lax
12. **响应头**：`X-Content-Type-Options` / `X-Frame-Options` / `Referrer-Policy` / `frame-ancestors` 齐备

## 功能清单

- **经营概览**：客户数、项目数、累计合同金额、进行中项目、附件总数、来源渠道分布、项目状态分布、行业分布、最近项目与操作动态、待审批提醒
- **客户管理**：关键词搜索（公司/联系人/电话/微信/地区/地址/备注）、渠道筛选、行业与等级筛选、分页与每页条数、增删改查、详情页含历史项目与附件数
- **项目管理**：按名称/客户/类型/状态筛选、金额合计、增删改查、附件管理
- **全局搜索**：顶部搜索框一次检索客户与项目（支持微信号、地区）
- **数据导出**：客户台账、项目台账导出 Excel（表头样式 + 自动列宽 + 自动筛选；无数据时导出模板表头）
- **多联系人**：一个客户可维护多个对接人（姓名/职位/电话/邮箱/微信/备注），可切换主联系人；
  主联系人自动同步到客户主档字段，列表展示、搜索、导出与查重沿用同一口径
- **列表排序与区间筛选**：客户列表支持按最近修改 / 最近录入 / 公司名称 / 客户等级排序，并按录入日期区间过滤；
  项目列表支持按最近录入 / 含税金额 / 结束日期 / 签订日期 / 项目名称排序，并按含税金额区间、结束日期区间过滤；
  排序与筛选条件都会带到导出的 Excel 里
- **客户跟进**：客户与项目详情页内置「写跟进 + 时间轴」，记录方式/内容/下次跟进；客户列表显示最近与下次跟进并可一键筛选到期
- **待办提醒**：由业务数据实时推导（跟进到期、项目 7 天内到期、应收逾期、待对账笔数），顶栏铃铛 + 侧边栏角标，可一键发到邮箱
- **合同要素**：项目支持合同编号、签订日期、付款条款、账期（用于逾期判定）与负责人；列表可按负责人筛选、按合同号搜索
- **回款计划**：项目可分期（期次/约定日期/金额/比例），收款项可关联期次，期次显示已收与剩余，逾期期次高亮
- **经营看板**：应收 / 已收 / 未收 / 逾期四项资金指标、近 6 个月签约与回款趋势、应收账龄分桶、负责人业绩 Top5
- **批量导入**：客户 / 项目 Excel 导入，提供模板下载 → 上传预览（逐行标注可导入/跳过/错误及原因）→ 确认写库；
  单次 500 行，重复记录自动跳过，项目导入按客户名匹配并反算不含税金额
- **客户查重**：新增 / 编辑客户时按公司名（忽略空格、括号差异）与联系电话查重，命中先提示已有记录，
  确认不是同一家后再保存，避免重复建档
- **回收站**：删除的客户 / 项目进入回收站，可按快照原样恢复（项目、收款、期次、跟进、附件一并回来），
  也可彻底删除并清理附件文件；仅管理员可操作
- **备份与恢复**：一键生成 zip（SQLite 在线快照 + uploads + avatars + manifest），可下载留存；
  恢复支持历史上传包与服务器备份，恢复前自动生成 `crm-before-restore-*` 备份，恢复后自动补齐结构
- **操作日志**：登录/注册/审批/通过/拒绝/新增/修改/删除/上传/下载/导出/导入/备份/恢复/锁定/解锁，
  支持按动作、对象类型、时间区间、操作人与关键字组合筛选，含操作人与 IP；普通成员仅见自己的日志
- **详情页内嵌操作记录**：客户与项目详情页直接展示本对象最近 8 条操作，可一键跳到已过滤好的完整日志
- **账号管理**：见上文「账号体系与注册审批」；管理员可直接新建账号（指定角色/状态/数据范围），支持修改登录账号名
- **权限管理**：角色 + 数据范围 + 项目级「查看/修改/删除」授权，支持按客户批量授权
- **批量操作**：客户与项目列表支持多选、全选，批量修改状态/类型/等级/行业与批量删除，逐条校验权限并统计跳过数
- **个人资料**：头像上传（≤2MB，jpg/png/gif/bmp/webp）、姓名、微信号、手机、邮箱、部门
- **行政区划**：客户「所在地区」为省/市/区三级联动（离线数据 34 省 2839 区县），无法匹配的历史值可手动填写
- **选项管理（后台字典）**：客户等级 / 行业类型 / 来源渠道 / 项目类型 / 项目状态 / 服务方式 / 付款方式 / 转账渠道
  全部集中在「选项管理」维护，支持新增、改名（可同步历史记录）、删除、上移下移排序、启用/停用与默认值设置；
  「其他」为内置兜底项，不可删除 / 停用 / 改名且恒在最底部；删除前检查引用条数，使用中的选项会被拦截并引导改为停用
- **局部自定义**：表单里的「自定义…」只作用于当前这条记录，不写入选项字典、不影响其他表单与筛选；
  自定义值可通过关键字检索（类型 / 状态 / 行业 / 渠道均已纳入搜索范围）
- **金额与税点**：合同金额（不含税）+ 税点（默认 6%）+ 含税价格双向换算，税点可改（含 0），前端即时联动、服务端复算
- **服务方式 / 付款方式**：默认远程服务 / 现场服务 / 远程+现场；支付软件转账 / 现金支付（均为可配置选项，
  带「转账」标记的方式登记收款时必须填流水号并参与对账，判定与名称解耦）
- **收款对账**：登记收款 → 待对账 → 对账通过才计入已收；流水号唯一校验、超收拦截、撤销对账、对账中心批量处理
- **导出二次确认**：导出客户 / 项目台账前弹自定义弹窗，说明导出字段与影响，确认后才执行
- **登录页品牌区**：右上角开发团队标识（渐变徽标 + 技术支持邮箱入口），页面底部为备案式技术支持信息条（团队 / 官网 / 邮箱 / 版权），固定在窗口底部
- **页脚**：页面底部同样展示团队技术支持信息，官网与支持邮箱可点击跳转
- **错误页**：404 / 413（上传超限）/ 500 友好提示
- **夜间模式**：亮色 / 暗色一键切换，偏好存 localStorage，刷新与下次访问自动恢复；登录页同样可切换

## 部署到 CentOS7

```bash
# 1. 上传代码到 /opt/crm，安装依赖并启动（内部自动建 venv、装依赖、初始化库、拉起 gunicorn）
cd /opt/crm && bash start.sh

# 2. Nginx 反向代理
cp deploy/nginx-crm.conf /etc/nginx/conf.d/crm.conf
nginx -t && systemctl reload nginx

# 3. 定时备份（crontab -e）
0 2 * * * /opt/crm/deploy/backup.sh >> /opt/crm/logs/backup.log 2>&1
```

Gunicorn 只监听 `127.0.0.1:8000`，公网入口全部由 Nginx 承担。

## 服务器部署（Nginx + Gunicorn + MySQL）

桌面版用 SQLite 单文件；服务器版把存储换成 MySQL 8，靠环境变量切换，业务代码零改动：

```
浏览器 --443--> Nginx --127.0.0.1:5050--> Gunicorn(Flask) --3306--> MySQL
```

- 配置项：`CRM_DB_HOST` 一设即走 MySQL（`CRM_DB_PORT/NAME/USER/PASSWORD` 配合），
  另有 `CRM_BEHIND_PROXY=1`（信任代理头）、`CRM_COOKIE_SECURE=1`（HTTPS 下 Cookie 带 Secure）
- 部署产物：`deploy/install.sh`（一键幂等安装）、`deploy/crm.service`、`deploy/nginx-crm.conf`、
  `deploy/crm.env.example`、`deploy/backup.sh`（mysqldump 冷备）
- 迁移工具：`tools/migrate_sqlite_to_mysql.py`（保留主键 id，逐表比对条数）
- 回归验证：`tests/run_mysql.sh`（同一套 283 项用例直接跑 MySQL）
- 完整步骤、参数与排错：`docs/deploy/CRM_部署手册.md`

## 迁移与备份

管理后台「数据与安全 → 备份与恢复」可一键生成完整备份（`crm.db` 一致性快照 + `uploads/` + `avatars/` + manifest），
文件落在数据目录的 `backups/` 下，可下载留存；换机器时把 zip 恢复过去即可，恢复后会自动补齐表结构。
手工迁移也只需同时搬走两样东西：`crm.db` 和 `uploads/` 整个目录。
`deploy/backup.sh` 仍可用于纯命令行的定时打包与 30 天轮转。
